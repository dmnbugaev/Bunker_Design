# Дизайн-кит «Бункера»

Хранилище всех дизайн-материалов проекта. Папка остаётся в репозитории,
но **не деплоится на Vercel** (исключена в `.vercelignore`) и не попадает
в продакшен-сборку сайта.

## Состав дизайн-системы

| Слой | Где живёт | Деплоится? |
| --- | --- | --- |
| UI-кит (13 компонентов `Ui*`) | `app/components/ui/` | да, часть сайта |
| Токены и базовые стили | `app/assets/css/` (tokens → base → components → pages) | да, часть сайта |
| Демо-страница кита | `design-kit/demo/` | нет |
| Библиотека референсов (~24 МБ исходников) | `design-kit/referens/` | нет |
| Документация (токены, компоненты, a11y, адаптив) | `docs/design-system/` | нет |
| Оптимизированные картинки сайта | `public/images/` (WebP) | да |

UI-кит — единственный канонический источник компонентов: кнопки, поля,
диалоги, скелетоны и т.д. импортируются из `app/components/ui/` самим
сайтом, отдельной «копии для демо» нет. Демо-страница ниже подключает те
же соглашения об именах через собственный снапшот стилей
(`demo/assets/styles/`), чтобы показывать кит без запуска Nuxt.

## Демо дизайн-кита локально

```bash
npm run design-kit   # http://127.0.0.1:4173/demo/
```

Демо — статическая страница (без сборки и зависимостей); сервер нужен
только потому, что ES-модули не работают по `file://`.

## Референсы и картинки сайта

`referens/` — исходная библиотека (постеры сети, «дымы», неиспользуемые
кадры). Сайт напрямую эти файлы не использует: нужные изображения
пережимаются в WebP и складываются в `public/images/` с осмысленными
именами:

```bash
node design-kit/tools/optimize-images.mjs
```

Соответствие «исходник → слаг» зафиксировано в карте внутри скрипта.
После генерации обновите ссылки, если меняли состав (фикстура каталога —
`scripts/make-fixture-catalog.mjs`, hero/о сети/партнёрство — страницы в
`app/`, дымы — `app/assets/css/pages.css`).
