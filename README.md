# Бункер — сайт сети вейпшопов

Справочный каталог и бронирование товаров в магазины сети «Бункер».
Функциональная основа перенесена с сайта ProHook, оформление — из
дизайн-системы «Бункера» (тёмная тема, коралловый акцент, BICUBIK/Akzentica
с fallback-цепочками, диагональные срезы, дымы).

## Правовая модель

Сайт — НЕ интернет-магазин (15-ФЗ ст. 19 запрещает дистанционную продажу
табачной и никотинодержащей продукции):

- витрина — справочный каталог: цены и наличие, без «купить» и корзины;
- покупка — только запрос на резерв в выбранный магазин (`/reserve`) и
  выдача на кассе после проверки совершеннолетия по документу;
- гейт 18+ и юридическая классификация категорий
  (`shared/legal/classification.ts`): неклассифицированные корневые папки
  «МойСклад» не публикуются;
- каталог, карточки товаров и поиск закрыты от индексации; изображения
  регулируемых товаров видны только совершеннолетним пользователям.

## Стек

Nuxt 4 (Vue 3, TypeScript, Nitro), собственный CSS по токенам дизайн-системы
(без UI-фреймворков), серверные сессии и файловые хранилища в `.data/`
(аккаунты — Argon2id, брони, заявки), «МойСклад» JSON API remap 1.2.

## Запуск (разработка)

```bash
npm install
npm run dev
```

По умолчанию сайт стартует в **фикстурном режиме** (`.env`:
`MOYSKLAD_SNAPSHOT_PATH=./tests/fixtures/catalog.json`): каталог берётся из
демо-снимка (12 товаров, 5 категорий, 3 демо-магазина в Саратове/Энгельсе),
бонусы отвечают тестовыми данными (телефон `+7 900 000-00-01` → баланс 500).
Реальные запросы к «МойСклад» в этом режиме не выполняются; в production
переменную не задавать.

Основные скрипты:

```bash
npm run dev            # dev-сервер (http://127.0.0.1:3000)
npm run build          # production-сборка (.output/)
npm run preview        # прогон production-сборки
npm run catalog:sync   # разовая выгрузка из «МойСклад» + проверка МРЦ
npm run stores:geocode # координаты магазинов (Яндекс/2ГИС) в sidecar
npm run test:unit      # юнит-тесты (node --test)
npm run test           # e2e-тесты Playwright (фикстурный режим)
npm run lint           # eslint
npm run typecheck      # vue-tsc
```

Демо дизайн-кита — локально: `npm run design-kit` (страница живёт в
`design-kit/demo/`, в деплой не попадает; см. `design-kit/README.md`).

## Подключение «МойСклад»

1. Создайте API-токен: online.moysklad.ru → Профиль → API-токены.
2. Заполните `.env` по `.env.example` (токен — только в `NUXT_MOYSKLAD_TOKEN`,
   никогда не коммитится) и уберите `MOYSKLAD_SNAPSHOT_PATH`.
3. `npm run catalog:sync` — проверьте состав выгрузки (товары/категории/
   магазины) и предупреждения о несопоставленных корневых папках.
4. Подробности: `docs/INTEGRATION.md`.

Токен используется только сервером; картинки отдаются через серверный
прокси (`/api/products/:id/images/:n`), в браузер секрет не попадает.

## Деплой

### Vercel (автоматический)

Репозиторий готов к импорту в Vercel без настройки: Nuxt определяется по
`vercel.json` (`framework: nuxtjs`), сборка — `npm run build`. Лишнее
(дизайн-кит 24 МБ, тесты, docs, CI-скрипты) не загружается — см.
`.vercelignore`.

Переменные окружения — в настройках проекта Vercel (список и назначение —
`.env.example`). Минимум для запуска: `NUXT_PUBLIC_SITE_URL`. Для
preview-деплоев с демо-каталогом добавьте
`MOYSKLAD_SNAPSHOT_PATH=./tests/fixtures/catalog.json`; для боевого
режима задайте `NUXT_MOYSKLAD_TOKEN` и не задавайте snapshot.

Ограничение serverless: файловые хранилища (аккаунты, брони, заявки) по
умолчанию уходят в `/tmp` и живут до холодного старта функции — регистрации
и резервы на Vercel эфемерны. Постоянство данных и Telegram-уведомления —
на VPS-деплое ниже или при подключении внешнего хранилища.

### VPS (с постоянством данных)

По образцу ProHook: node ≥ 24, сборка на сервере (или перенос `.output/`),
systemd-юнит на `node .output/server/index.mjs`, nginx как реверс-прокси на
порт 3000. Env-переменные — в окружении юнита (`EnvironmentFile=/srv/bunker/.env`),
`.data/` — на постоянном томе (аккаунты/брони/заявки), резервное копирование
обязательно. HTTPS обязателен (геолокация и cookie).

## Структура

- `app/` — страницы, компоненты (UI-кит — `app/components/ui/`), композиции,
  стили (`app/assets/css/`: tokens → base → components → pages);
- `server/` — API-эндпоинты, сервисы «МойСклад» (каталог, контрагенты,
  бонусы), файловые хранилища, сессии;
- `shared/` — общий код клиента и сервера (типы, валидация, юридический
  слой, SEO, контактные данные);
- `public/` — только то, что отдаёт сайт: `brand/`, `images/` (WebP),
  верификация Яндекса; шрифты `fonts/` кладутся вручную (NEEDS-DATA);
- `design-kit/` — дизайн-кит: демо дизайн-системы, библиотека референсов,
  генератор `public/images/` (в деплой не попадает — `.vercelignore`);
- `tests/` — unit (`*.test.mjs`) и e2e (`*.spec.ts`) + фикстура каталога.
